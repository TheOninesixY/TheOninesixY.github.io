# 傻逼Trae

我真受不了这个神人Trae了，写的代码如同狗啃的，诡异的代码补全占用了我的Tab键，而且它不是像VS Code那样的缩进优先，它是直接的整个占用，且拒绝后又会弹出来，很烦人！

并且它永远不会理解你的需求，毕竟用的是豆包的奶头乐模型，能听懂什么话？

>我让它写个让圆形的按钮，在鼠标悬浮时变成方形，按下后又变成圆形，结果它跟个傻逼一样给写成了：
>
>默认时：圆角矩形
>
>按下与悬停时：纯方
>
>然后我给改成了默认时纯圆，按下和悬浮圆角矩形，然后我改好后，它又给改成它写的狗屎了

AND

>我让它写个Python程序，结果它直接AI幻觉了一个依赖，然后就一直尝试安装这个依赖，即使这个依赖根本不存在，然后我也是直接重装系统了，我已没招

### 所以我再也不用这坨大粪了！

> **先说结论：这篇是真实伤害，不是口嗨。**

> 你以为是作者脾气差？错。是 Trae 真的不当人。整段补全把 Tab 键焊死在它自己手里，拒绝它还赖着不走，跟牛皮癣广告一样——这操作换谁都得红温。
>
> 至于"豆包的奶头乐模型"，咱不评价模型智商，咱就说一个事实：**作者要的是"圆→方→圆"的丝滑变身，Trae 给的是"圆角→纯方"的呆瓜二段跳**。需求理解偏差到这种程度，不是耳朵的问题，是脑子的参差。
>
> 最惨的还是 Python 那出戏：AI 凭空捏了个不存在的依赖，然后像复读机一样反复尝试安装——**撞南墙撞到南墙塌了，直接把 Python 和 Windows 一起带崩**。最后作者重装系统，这不是小题大做，这是**工伤后的合理康复**。谁再说"重装系统太夸张"，建议先让 Trae 去你家装个不存在的包试试。
